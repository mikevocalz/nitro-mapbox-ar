# Changelog

All packages in this repository share one version. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [0.1.0] - unreleased

Pre-release `0.1.0-alpha.0`, not yet published. Publish steps are in [docs/RELEASE.md](docs/RELEASE.md).

First release under the `@mikevocalz` scope. Every break from the earlier `@mapbox/react-native-mapbox-ar*` code is listed in [docs/MIGRATION.md](docs/MIGRATION.md).

### Added

- `@mikevocalz/nitro-mapbox-ar`: the `MapboxAR` C++ root generated by Nitrogen 0.37.1, holding one process-wide `accessToken` and decoding Terrain-RGB with `decodeTerrainRgb` (sync, up to 1 MiB) and `decodeTerrainRgbAsync` (worker queue).
- `@mikevocalz/nitro-mapbox-ar/core`: plain ESM build with no React Native, Nitro, Skia or WebGPU imports, enforced by `scripts/check-core-imports.mjs`. JS clients accept any `FetchLike`.
- `MapboxNavigationClient.directionsWithRequestUrl()`, which returns the request URL native trip sessions need.
- `@mikevocalz/nitro-mapbox-ar-maps`: Mapbox Maps SDK 11.32.0 on iOS and Android. `MapboxMaps` root (`isMapViewAvailable`, `sdkVersion`, `capabilities`), `MapboxMapView` with async camera, style, query and annotation methods, `MapStyle` handles per style load, `PointAnnotationManager`, `RenderedFeature`.
- `@mikevocalz/nitro-mapbox-ar-navigation`: Mapbox Navigation SDK 3.32.0 on iOS and Android. `MapboxNavigation.createTripSession()` with progress, reroute and error listeners, electronic horizon, and replayed drives; `createNativeNavigationProvider` adapts a session to `NavigationSession`.
- `@mikevocalz/nitro-mapbox-ar-specs`: `routeToPlaces` and `userPositionToProgress` for the Snap Spectacles Navigation Kit, compiled against `/core` in `examples/specs-lens`.
- `@mikevocalz/nitro-mapbox-ar-reactvision`: `getSpatialHostCapabilities` and `createViroSpatialHostProbe`; compass placement, route chevrons, route matching, buildings and satellite ground.
- Reference app: Quest tabletop route over passthrough, a visionOS scene rooted in `ViroScene`, design tokens, a copy module, and an accessibility pass ([docs/reference-app/A11Y.md](docs/reference-app/A11Y.md)).
- Release gates: Nitrogen output committed and diffed in CI, TypeDoc with warnings as errors and undocumented exports failing the build, tarball checks for entry points, LICENSE and stray build caches, the API sketch typecheck.

### Changed

- Package names: `@mapbox/react-native-mapbox-ar` → `@mikevocalz/nitro-mapbox-ar`, `-native-map` → `-maps`, `-reactvision` and `-agent-mcp` keep their suffix.
- Every `MapboxMapView` method returns a Promise, including camera reads (`getCamera()` → `getCameraState()`).
- `styleURI` prop → `styleUri`, taking a full URI; presets moved to `MapStyles`.
- `MapCapabilities` is read from the `MapboxMaps` root, not the view.
- `canShareColocationFrame` takes two `ColocationPeer`s; `ColocationPlatform` is an open `string`.
- React Native 0.86, Expo SDK 57, Viro 3.0.3, Skia 2.14.0, react-native-webgpu 0.13.0, TypeGPU 0.12.7.

### Removed

- `getMapboxARCore()`, `setAccessToken`, `getAccessToken`, `hasAccessToken`, `assertAccessToken`: use `MapboxAR.accessToken`.
- The `MapboxMapView` `accessToken` prop.
- `ReactVisionPlatform`, `ReactVisionRuntimeCapabilities`, `normalizeReactVisionCapabilities` and `graphiteOnVisionOS`: use `SpatialHostCapabilities` from `getSpatialHostCapabilities`.
- The 2018 React Native 0.50 / react-viro 2.x runtime and its Objective-C and Java terrain generators ([docs/LEGACY_2018.md](docs/LEGACY_2018.md)).

### Not verified

- No FPS, TTI or memory figure has been measured on iPhone, Pixel or Quest 3 ([docs/PERFORMANCE.md](docs/PERFORMANCE.md)).
- The reference app's accessibility fixes were reviewed from source, not with a screen reader on a device.
